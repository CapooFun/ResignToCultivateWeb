# 文档与工作流规范

**最后更新**: 2026-08-04

## 1. 存放边界

| 用途 | 目录 |
|------|------|
| 定稿设计 | `项目管理/10_📐设计文档/` |
| 开发过程记录 | `项目管理/20_📅开发日志/YYYY-MM/` |
| 里程碑 / 验收 | `项目管理/30_📦版本快照/` |
| 可复用踩坑 | `项目管理/60_🔧经验扩展/` |
| 未定稿方案 / 审查 / 讨论 | `项目管理/00_中转站/` |
| 规则扩展 | `项目管理/50_📏规则手册/` |
| 术语与速查 | `项目管理/70_📚参考资料/` |
| 作者待办 | `项目管理/0_0制作人工作台/作者待办记事本.md` |
| 玩法权威规格 | Infans_Vault `辞职修仙传/`（不进本仓定稿冒充权威） |

禁止把成篇设计或长总结直接堆在仓库根目录（根目录仅保留 `README.md`、`开发交接.md` 等入口）。

## 2. 生命周期

1. **中转站**：审查、方案、讨论、总结优先放 `00_中转站/`；结案后升格到设计层，或进垃圾箱，或删除。
2. **开发日志**：按日/按次记录；可复用结论提炼到 `60_🔧经验扩展/`。
3. **版本快照**：与 `package.json` version 或重要里程碑对齐。

## 3. 文档头（建议）

- `**版本**`：与 `package.json` 或里程碑一致
- `**最后更新**: YYYY-MM-DD`

涉及存档字段、内容表契约时，改前评估影响面，并以 `src/game/types.ts` / `content.ts` 为工程事实来源。

## 4. Git

- 日志与快照默认基于本地 git 状态撰写。
- **不擅自 `git push` / 不擅自 commit**；须 Capoo 明确要求。
- 禁止提交 `node_modules/`、`dist/`、`test-results/`、凭据；不把 Vault 私人数据打进本仓。

## 5. 验证习惯

改完跑相关验证：至少触及的单测 / `npm run check`；必要时 `npm run test:e2e`。不删测试、不作假断言。
